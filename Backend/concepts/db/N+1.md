## N+1 문제란 뭘까?
repository 메서드로 조회할 때, 처음 1번 엔티티 조회와, 연관 엔티티 n개를 조회하게 되는데
쿼리문을 n+1개를 사용하는 문제를 말한다.

이게 왜 문제되냐면, db 성능 저하를 유발하고 조회 속도도 느려진다.
## 해결방법

### fetch join
```
@Query("""
select p
from Post p
join fetch p.user
""")
List<Post> findAllWithUser();
```
필요한거 한번에 다가져옴.->n+1이 안 발생함. 가장 많이 씀

### entitygraph
```
@EntityGraph(attributePaths = "user")
List<Post> findAll();
```
fetch join이랑 비슷하게 한번에 가져오는데 구현이 훨씬 간단함.
### batch fetch
```
spring.jpa.properties.hibernate.default_batch_fetch_size=100
```
100개의 엔티티를 한번에 가져온다. n+1을 1+1, 1+2정도로 줄일 수 있다.
